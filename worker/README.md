# price-proxy — 계산기용 Cloudflare Worker

계산기(`../index.html`)가 쓰는 서버리스 함수. 엔드포인트는 세 개다.

| 경로 | 하는 일 |
|---|---|
| `GET /?url=<상품 URL>` | 상품 페이지에서 **가격만** 파싱해 JSON |
| `GET /rate?store=<슬러그>` | Rakuten·TopCashback **캐시백 요율을 그 한 곳만** 라이브 조회 (v0.29) |
| `POST /vision` | 사진에서 **검색어 후보**를 뽑아 JSON (v0.31) |

## 왜 필요한가

계산기는 GitHub Pages에 올라간 정적 페이지라 다른 사이트를 직접 못 부른다(CORS).
그래서 공개 CORS 프록시 3개를 돌려썼는데, 2026-08-11 점검 결과:

| 프록시 | 상태 |
|---|---|
| corsproxy.io | ❌ HTTP 403 |
| api.allorigins.win | ❌ 무응답 |
| r.jina.ai | ✅ 동작 |

살아있는 건 하나뿐인데 순서상 마지막이라, 가격 하나 읽는 데 20초를 기다린 뒤에야
값이 떴다. 사용자 입장에선 "자동조회가 안 된다"로 보였다.

## 배포 (한 번만)

Cloudflare 계정이 필요하다. 무료 플랜으로 충분하다(10만 요청/일).

```bash
cd site/worker
npx wrangler login
npx wrangler deploy
```

배포되면 이런 URL이 나온다:

```
https://purchase-optimizer-price.<계정이름>.workers.dev
```

이 URL을 `site/index.html` 의 `PRICE_API` 상수에 넣고 커밋·푸시하면 끝이다.
비워두면 계산기는 기존 공개 프록시 체인으로만 동작한다(성공률 낮음).

## 확인

```bash
curl "https://purchase-optimizer-price.<계정>.workers.dev/?url=https://www.crocs.com/p/207021.html"
```

```json
{ "price": 34.99, "title": "…", "status": 200 }
```

## API — `POST /vision` (v0.31, 사진에서 검색어 후보)

사진 한두 장을 받아 **검색어 후보**를 돌려준다. 가격도, 최저가도, 상품 확정도 아니다.

> 근거 문서: `리서치/사진-상품인식-조사.md` (설계) · `리서치/workers-ai-비전-실측-2026-08-20.md` (모델 선택)

### ⚠️ 켜려면 키가 필요하다 — 키가 없으면 버튼이 아예 안 뜬다

```bash
cd site/worker
npx wrangler secret put VISION_API_KEY     # 콘솔에서 붙여넣기 (repo 에 안 들어간다)
npx wrangler deploy
```

계산기는 로드할 때 `POST /vision` 에 `{"images":[]}` 를 한 번 보내 **켜져 있는지만** 확인한다
(제공자를 부르지 않고 응답 코드만 갈린다. 사진도 사용자 데이터도 안 나간다).
키가 꽂혀 있으면 `bad-request` 가 오고 그때만 📷 버튼을 켠다.

⭐ **판정은 opt-in 이다** — "켜졌다는 신호가 있을 때만 켠다". 처음엔 반대로 짰다가 실제로 틀렸다:
`/vision` 이 없는 **옛 워커**가 배포돼 있으면 405 를 주는데 거기엔 `errorCode` 가 없어서
"꺼짐 신호 없음"이 되고 **버튼이 켜져 버렸다.** 페이지가 워커보다 먼저 배포되는 건 정상적인 일이라
opt-in 이 맞다. 이 계약은 하니스가 못 박는다(`images:[] → bad-request`).

### ⚠️ 배포 전에 반드시 — 상한 두 개

**엔드포인트는 공개돼 있다.** 누가 스크립트로 이미지를 10만 장 던지면 Haiku 기준 $164다.

| # | 무엇 | 어디서 | 왜 |
|---|---|---|---|
| 1 | **제공자 콘솔의 월 예산 상한** | Anthropic/Google 콘솔 | **금액 상한이 최후의 안전장치다.** 잊지 말 것 |
| 2 | **엣지 레이트리밋** | Cloudflare 대시보드 | 코드로 IP 리밋을 넣으면 요청자 식별 정보를 들고 있어야 해서 **프라이버시 조건 2와 정면으로 부딪힌다.** `/rate` 에서 이미 내린 것과 같은 결정 |

클라이언트에도 하루 상한(localStorage 20장)이 있지만 **지우면 그만이라 방어가 아니다** —
정직한 사용자가 실수로 폭주하는 걸 막고 "오늘은 여기까지예요"를 띄우는 자리다.

### 제공자 — 기본값은 Anthropic

| 변수 | 기본값 | 뜻 |
|---|---|---|
| `VISION_API_KEY` | (없음) | **secret.** 없으면 기능이 꺼진다 |
| `VISION_PROVIDER` | `anthropic` | `anthropic` \| `gemini` |
| `VISION_MODEL` | `claude-haiku-4-5` / `gemini-2.5-flash-lite` | 모델 덮어쓰기 |
| `VISION_GEMINI_PAID_TIER` | (없음) | Gemini 를 쓰려면 `confirmed` 여야 한다 (아래) |
| `VISION_BASE_URL` | 제공자 공식 주소 | AI Gateway 등으로 우회할 때 |

**왜 Anthropic 이 기본인가** (조사 4-B):
- *"이미지는 요청 처리 후 삭제 · 학습에 안 씀"* 을 명문화한 유일한 곳이다 → 고지 문구가 그대로 쓰인다
- ⭐ **무료 티어가 없다.** Gemini 무료 티어 약관에는 *"human reviewers may read, annotate, and
  process your API input and output"* 가 있다 — **사람이 사용자의 매장 사진을 읽는다.**
  그런데 **키만 봐서는 무료인지 유료인지 알 수 없다.** Anthropic 에는 그 함정 자체가 없다.
- 비용: 사용자 1,000명 월 $29.5 (Gemini Flash-Lite 면 $2.34 — 12배 싸다)

**Gemini 로 바꾸려면** 유료 티어임을 명시적으로 확인해야 한다. 코드로는 구분이 불가능해서,
운영자가 직접 켜게 만들었다. 안 켜면 요청이 거부된다:

```bash
npx wrangler secret put VISION_API_KEY          # Gemini 키
# wrangler.toml 의 [vars] 에 VISION_PROVIDER = "gemini"
#                            VISION_GEMINI_PAID_TIER = "confirmed"
```

이 플래그를 켜는 것은 *"이 키는 유료 티어이고, 따라서 사람이 사진을 읽지 않는다"* 는 선언이다.
**무료 키에 이걸 켜면 고지 문구가 거짓이 된다.**

### 요청·응답

```
POST /vision
{ "images": ["<base64 JPEG>", ...],  // 1~2장. 클라이언트가 1024px·q0.75 로 줄여서 보낸다
  "lang": "ko" | "en" }
```

```json
{ "ok": true,
  "category": "운동화",
  "candidates": [ { "query": "Nike Air Max 90 white red", "why": "중창의 'AIR MAX' 각인" } ],
  "read":    ["Nike 스우시 로고", "AIR MAX"],
  "guessed": ["UNVERIFIED:90"],
  "ask": null }
```

실패는 `{ "ok": false, "errorCode": ..., "error": ... }` 다.
`no-key` · `bad-request` · `too-large` · `provider-error` · `provider-refused` ·
`gemini-tier-unconfirmed` · `bad-config`.
**실패했을 때 추측한 검색어를 대신 내놓지 않는다** — 화면은 "지금은 안 돼요"로 끝난다.

### ⭐ 설계의 급소 — 신뢰도를 안 묻는다

모델이 말하는 신뢰도 숫자는 못 쓴다. verbalized confidence 는 **80~100% 에 5의 배수로 몰려서**
(ICLR 2024) `confidence < 70 이면 되묻기` 같은 게이트는 **열리지 않는 문**이다.

그래서 신뢰도 대신 **사실 보고**를 시킨다:
- `read` = 이미지에서 **실제로 읽은 글자**
- `guessed` = 짐작
- 후보 여러 개 — **갈리는 것 자체가 불확실성 신호**다(Google PAIR 의 N-best 권고)

그리고 **되묻기 판단은 모델의 `ask` 가 아니라 `read` 가 비었는지로 한다**(클라이언트 `needsReask`).
실측에서 모델은 못 읽었을 때도 **12/12 확신했다.**

### ⭐ `auditGuessed()` — 이 엔드포인트에서 가장 중요한 함수

실측에서 모델은 `OLED65C2` 를 `OLED-D65C2` 로, `KX-7742B` 를 `KX-7744B` 로 읽고
**그것을 `read`(= 실제로 읽은 글자) 에 넣었다.** 화면에는 *"박스에서 …를 읽었어요"* 로 나가므로,
그대로 두면 **거짓말이 사용자 눈앞에 인쇄된다.**

모델이 정직해지게 만들 방법은 없다. 대신 **검색어에 들어간 모델번호가 `read` 에 뒷받침되는지
우리가 대조한다.** 뒷받침이 없으면 정의상 짐작이므로 `guessed` 로 옮기고, 화면에
⚠️ *"'…'는 사진에서 확인하지 못했어요"* 가 뜬다.

- 무엇을 모델번호로 보나: **영문자와 숫자가 섞인 4자 이상 토큰.**
  `OLED65C2`·`KX-7742B`·`WH-1000XM5` 는 걸리고, `Nike`·`sneakers`·`65` 는 안 걸린다.
- 순수 숫자를 뺀 이유: "65인치" 같은 치수는 한 글자 틀려도 검색 결과가 눈에 띄게 어긋나서
  사용자가 바로 안다. **모델번호는 그렇지 않다.**
- 대조는 **구두점을 지우고** 한다 — `read` 에 `OLED65C2`, 검색어에 `OLED-65C2` 로 나오는 경우를
  다른 값으로 세면 **멀쩡한 걸 짐작이라고 표시**하게 된다.

### 프라이버시 — 조건 5개 중 **하나는 못 지킨다**

`/rate` 의 5개 조건을 그대로 대보면:

| # | 조건 | `/vision` |
|---|---|---|
| 1 | 로그 안 남김 | ✅ `console.*` 0개 + `[observability] enabled = false` |
| 2 | IP 저장 안 함 | ✅ `headers.get` 은 `Origin` 한 곳뿐 — **그래서 IP 레이트리밋을 코드로 못 넣는다** |
| 3 | 공용 캐시 | 🔴 **못 지킨다.** 이미지는 사람마다 달라 캐시 키를 만들 수 없다 |
| 4 | 고지 카드 명시 | ✅ `index.html` 의 `disc.data.vision` |
| 5 | 이 기능 없이도 작동 | ✅ 상품명 직접 입력이 원래 경로다 |

**조건 3이 깨지는 걸 숨기지 않는다.** 대신 그 자리를 **"통과시키고 버린다"** 로 채운다 —
사진을 R2·KV·D1 어디에도 넣지 않는다. `wrangler.toml` 에 스토리지 바인딩이 하나도 없는 것이 그 근거다.
Cloudflare 문서가 *"may be stored by Cloudflare **if you specifically use a storage service**"* 라고
명시하고, 우리는 안 쓴다.

⚠️ **AI Gateway 를 쓸 거면 로그를 반드시 꺼라.** 기본값이 **프롬프트와 응답(= 사진과 인식 결과)을
로그에 저장**한다. 코드에 `cf-aig-collect-log: false` 를 항상 박아 뒀지만, **대시보드 옵트아웃도
같이 해야 한다.** 헤더만 믿으면 실수로 빠졌을 때 조용히 사진이 쌓인다.
헤더가 붙어 나가는지는 하니스가 검사한다.

변형에서 `ask` 가 `null` 이 되는데, 골든의 술어가 `g.ask.reason` 을 그냥 파고들어 **예외를 던져
하니스 프로세스를 통째로 죽였다.** 음성 대조군에는 그게 `실행오류` 로 찍혀서 *"이 검사가 살아있는지
알 수 없는"* 상태가 됐다. → **술어가 던지면 실패로 센다**로 고쳤다. 검사는 던지면 안 된다.

⚠️ `negcontrol-worker.mjs` 의 변형 문자열은 **워커 소스를 한 줄씩 리터럴로 찾는다.**
`handleVision` · `normalizeVision` · `auditGuessed` 를 고치면 그 문자열도 같이 고쳐야 하고,
안 고치면 `소스변경: false` 로 찍힌다. **그 값이 `false` 인데 실패가 0이면 통과가 아니라 헛돈 것이다.**
(실제로 `/rate` 라우팅 변형이 이번 리팩터로 한 번 깨졌다 — 12/12 가 11/12 로 떨어져서 알았다.)

### 한계 — 정직하게

- **모델번호는 여전히 이 기능의 약점이다.** 인쇄돼 있으면 읽지만, 인쇄 안 돼 있으면 추측이고
  그 추측은 틀릴 수 있다. `auditGuessed` 는 **틀리는 걸 막지 못하고, 짐작이라는 사실을 드러낼 뿐이다.**
- **TV·대형가전·창고형 매장 물건은 잘 안 된다.** 바코드와 같은 이유(매장 전용 모델)다.
  다만 사진 경로에는 탈출구가 있다 — *"모델명 스티커를 찍어 달라"* 는 되묻기.
- **실제 매장 사진에서의 정확도는 아직 안 쟀다.** 지금까지의 실측은 합성 이미지 + Workers AI 탈락뿐이다.
  채택한 모델(Haiku)로 **실물 20장**을 찍어보는 것이 남아 있다(조사 8장 0단계).


## API — `/rate?store=<슬러그>` (v0.29, 온디맨드 요율 조회)

요율 사전(`../rates.json`)은 **114곳**뿐이고, 그 밖의 판매처는 계산기에서 *"0%가 아니라
**모름**"* 으로 뜬다. 전수 수집(Rakuten 4,743 · TopCashback 9,826)은 **하지 않기로 확정**됐다 —
병목은 파일 크기가 아니라(gzip 실전송 170KB) 지속가능성이다. 일 2만 요청·월 85 러너시간에
차단 위험이 크고, **차단당하면 지금 잘 도는 114곳까지 같이 죽는다.** 1만 곳을 얻으려다
114곳을 잃는 거래다.

그래서 벌크 대신 **사용자가 실제로 물어본 한 곳만** 그때 조회한다.

```bash
curl "https://<워커>/rate?store=nike"
```

```json
{
  "store": "nike",
  "checkedAt": "2026-08-17T…Z",
  "rk":  { "pct": 10, "listed": true,  "status": "found" },
  "tcb": { "pct": 10, "listed": true,  "status": "found" }
}
```

포털별 결과는 **넷 중 하나**다. 이 넷을 뭉개지 않는 게 이 엔드포인트의 핵심이다.

| `status` | 값 | 뜻 |
|---|---|---|
| `found` | `pct: 8` · `upTo: true`(≤8%) · `flat: 5`($ 고정) | 요율 확인 |
| `listed-zero` | `pct: 0, listed: true` | **진짜 0%** — 등재돼 있는데 캐시백이 없다(쿠폰만) |
| `no-page` | `pct: null, listed: false` | 그 슬러그로는 상점 페이지가 없다 |
| `lookup-failed` | `pct: null, listed: null, error` | **모름** — 조회가 실패했다 |

`pct`·`listed`·`upTo`·`flat` 은 `rates.json` 과 **같은 이름·같은 뜻**이라 계산기가 그대로
꽂아 쓸 수 있다. `status` 만 추가 필드다.

> ⚠️ **실패는 절대 0%로 돌려주지 않는다.** "못 찾았어"와 "0%"는 다른 값이고, 0%로 뭉개면
> 계산기가 그 판매처를 조용히 깎아서 순위를 뒤집는다(v0.20 원칙). 하니스가 이걸 행 단위로
> 못 박고 있고, 일부러 뭉개는 변형을 넣으면 26건이 실패한다.

### 왜 이쪽이 `/?url=` 보다 공격면이 좁은가

`/?url=` 은 **임의의 호스트**를 받아서 나쁜 곳을 걸러낸다(거부 목록 방식). `/rate` 는 반대다:

- 사용자가 주는 건 URL이 아니라 **슬러그 하나**뿐이고, `/^[a-z0-9](?:[a-z0-9-]{0,58}[a-z0-9])?$/`
  를 통과해야 한다. 점·슬래시·콜론·`@`·`%` 가 없으니 **경로를 벗어나는 문자열을 만들 수 없다.**
- 목적지는 코드에 박힌 두 형태뿐이다 — `https://www.rakuten.com/shop/<슬러그>` ·
  `https://www.topcashback.com/<슬러그>/`
- 리다이렉트는 따라가되 **호스트가 그 포털 도메인을 벗어나면 즉시 중단**한다
  (`isPinnedUrl`). `/?url=` 쪽의 "사설 IP가 아니면 통과"보다 강하다 —
  포털이 302로 아무 데나 보내도 안 따라간다. **A11(DNS 리바인딩)이 여기엔 해당되지 않는다.**

### 프라이버시 — 조건 5개와 그 근거 위치

이 엔드포인트는 서버가 *"이 사용자가 어떤 매장을 궁금해했는지"* 를 잠깐 보게 만든다.
그건 쇼핑 이력이고 `프라이버시-원칙.md` 의 **H3**(읽은 데이터는 기기 밖으로 안 나간다)와
부딪힌다. 기각은 아니지만 조건부이며, 조건은 **문서상 약속이 아니라 지목 가능한 위치**로 있다.

| # | 조건 | 근거 위치 | 하니스 |
|---|---|---|---|
| 1 | 조회 매장명을 어떤 형태로도 기록·집계하지 않는다 | `index.js` 전체에 `console.*` **0개** + `wrangler.toml` 의 `[observability] enabled = false` | `/rate` 처리 중 `console.*` 호출 수 = 0 |
| 2 | IP·요청자 식별 정보를 저장하지 않는다 | `request.headers.get` 을 부르는 곳이 **`Origin` 한 군데**뿐. `CF-Connecting-IP`·쿠키·UA·`request.cf` 를 읽지 않는다 | — (정적 확인) |
| 3 | 엣지 캐시는 매장 단위 공용 캐시만 | `handleRate` 의 `cacheKey` 재료가 **슬러그 하나**뿐 | 오리진이 달라도 2차가 캐시 히트 · 대소문자만 다르면 같은 항목 |
| 4 | 고지 카드에 이 엔드포인트를 명시 | `index.html` `#disclosures` | — |
| 5 | 이 기능 없이도 도구가 작동 | 미등록 매장은 지금처럼 "모름" + 직접 입력 | — |

⚠️ **`[observability] enabled = true` 였던 걸 v0.29에서 껐다.** 켜져 있으면 Cloudflare가
요청 URL(= 매장 이름, `/?url=` 쪽은 상품 URL 통째로)을 며칠 보관한다. **이 설정은 재배포해야
적용된다.** 디버깅이 필요하면 `wrangler tail` 로 그때만 실시간으로 보고 켜 두지 않는다.

정직한 요약은 이렇게 된다 — *"서버는 매장 이름 하나를 잠깐 볼 뿐이고, 누가 물었는지는 모른다."*

### 캐시

매장 단위 공용, 성공 **6시간** / 실패 **2분**. 포털 기본율은 하루 단위로 움직이니 6시간이면
충분하고, 실패를 6시간 물고 있으면 일시적 봇 차단이 "모름"으로 굳어버린다.

### 한계

- **슬러그는 호출자가 준다.** TopCashback은 `dsw` 가 아니라 `dsw-us` 처럼 `-us` 접미사인
  상점이 있어서, `no-page` 가 곧 "그 포털에 없다"는 뜻은 아니다 — **"이 이름으로는 못 찾음"**
  이다. 계산기가 `-us` 를 한 번 더 시도하는 건 호출자 쪽 판단이다.
- **CapOne Shopping은 없다.** CAPTCHA로 자동 수집을 막고 있어 `rates.json` 에서도 수동
  갱신이다.
- **남용 여지.** 아무나 `/rate?store=…` 를 두들기면 포털로 요청이 2건씩 나간다. 슬러그를
  1만 개 훑으면 그게 정확히 우리가 피하려던 벌크 부하다. 코드 쪽 방어는 6시간 캐시뿐인데,
  **IP 단위 레이트리밋을 코드로 넣으려면 요청자 식별 정보를 들고 있어야 해서 조건 2와
  정면으로 부딪힌다.** 그래서 안 넣었다. 필요해지면 Cloudflare 대시보드의 엣지
  Rate Limiting 규칙(우리 손에 데이터가 안 남는 방식)으로 거는 게 맞다.
- **파서가 두 곳에 있다.** `scripts/update-rates.mjs` 와 규칙이 같다. 포털이 마크업을 바꾸면
  **두 곳을 같이 고쳐야 한다.** (실측 2026-08-17: Rakuten `<title>` · TCB `merch-offer__rate`
  둘 다 그대로 살아 있다.)

## API — `/?url=<상품 URL>` (가격 조회)

| 필드 | 뜻 |
|---|---|
| `price` | 파싱된 가격(숫자). 못 찾으면 `null` |
| `title` | og:title 또는 `<title>` — 계산기가 URL 슬러그로 추정하는 것보다 정확하다 |
| `status` | 원 사이트의 HTTP 상태 |
| `cached` | 30분 캐시에서 나온 응답이면 `true` |
| `error` | 실패 사유(사람이 읽는 문장) |

가져오기에 실패해도 **HTTP 200에 `price: null`** 로 응답한다. 계산기가 조용히
"직접 입력" 안내로 넘어가게 하기 위해서다.

## 설계상 정한 것

- **HTML을 그대로 돌려주지 않는다.** 가격만 파싱해 반환한다 → 아무나 쓰는 범용
  오픈 프록시가 되는 걸 막고, 응답 크기도 훨씬 작다.
- **SSRF 차단 — IP 리터럴은 전부 거부하고 도메인만 허용한다.** 사설 대역을 나열하는
  방식은 변종이 나올 때마다 뚫린다(퍼즈에서 `[::ffff:127.0.0.1]`이 통과했다). 상품 URL이
  raw IP인 경우는 없으므로 형태를 가리지 않고 막는 쪽이 단순하고 강하다.
  이름에 사설 IP가 박힌 와일드카드 DNS(`169.254.169.254.nip.io`)도 좁게 막는다.
  ⚠️ 임의의 도메인이 사설 IP를 가리키는 **DNS 리바인딩 일반**은 여전히 막지 못한다 →
  아래 [퍼즈 테스트 결과](#퍼즈-테스트-결과-2026-08-11) 참고.
- **리다이렉트는 직접 추적하고 홉마다 재검사** — `redirect:'manual'`. 자동 추적을 쓰면
  호스트 검사가 최초 URL에만 걸려서, 공개 URL이 302로 내부 주소를 가리키면 통과한다.
  최대 5홉.
- **본문은 상한까지만 읽는다** — `res.text()`는 자르기 전에 전부 버퍼링하므로 거대 응답에서
  메모리 한도에 걸린다. 스트림을 `MAX_BYTES`(4MB)까지만 읽고 끊는다. 단 읽기 루프의 종료 조건은
  두 개(`total < MAX_BYTES && out.length < MAX_HTML`)라, 일반적인 ASCII HTML에서는
  **글자 수 상한 `MAX_HTML`(2,000,000자)에 먼저 걸려 대개 2MB 부근에서 끊긴다**.
  4MB는 멀티바이트 응답까지 감안한 바이트 천장이지 실제 절단 지점이 아니다.
- **30분 캐시** — 같은 상품을 여러 번 열어도 원 사이트엔 한 번만 간다.
- **CORS 허용 오리진 고정** — `ALLOW_ORIGINS` 배열(배포 도메인 + `null` + 흔한 로컬 포트).
  정규식 반사는 쓰지 않는다 — 허용목록 밖의 값이 헤더에 실려나가면 안 되기 때문.

## 한계 (중요)

**서버를 둔다고 봇 차단이 풀리지는 않는다.** CORS만 사라진다.

배포 후 실측(2026-08-11, 8곳)은 **Nike ✅ · Crocs ⚠️(추측값) · 나머지 6곳 ❌**.
Amazon·Walmart·Home Depot는 봇 차단 페이지를 돌려준다.

주의할 점: **같은 코드가 로컬 Node에선 Amazon `$249`를 읽었는데 Cloudflare에선 차단됐다.**
"Cloudflare IP가 AWS보다 덜 막힌다"는 기대는 최소한 Amazon에는 맞지 않는다 —
Workers 대역은 널리 알려져 있어 오히려 먼저 차단된다. 워커의 이득은 성공률이 아니라
**CORS 제거 + 죽은 공개 프록시 의존 탈피 + 정확한 파싱(JSON-LD·`priceAmount` 우선)**이다.

### 폴백이 오히려 틀린 값을 줄 수 있다 (중요)

계산기는 워커가 실패하면 공개 프록시(`r.jina.ai`)로 넘어간다. 그런데 jina는 HTML을
마크다운으로 뭉개서 넘기기 때문에 JSON 키가 사라지고 **본문 `$` 텍스트만 남는다.**

실측: 같은 Amazon 상품($249)을 **jina 경유로는 `$35.99`** 로 읽었다. 워커는 같은 URL에
"봇 차단"이라고 정직하게 실패했는데, 폴백이 그 자리를 틀린 값으로 메운 것이다.

그래서 워커는 `confidence`를 함께 돌려주고(`high` = JSON-LD·메타·JSON키, `low` = 본문 텍스트),
계산기는 **`low`면 가격을 자동 입력하지 않고 "이 값 넣기" 버튼으로 확인을 받는다.**
틀린 가격은 없는 것보다 나쁘다 — 판매처 순위를 조용히 뒤집기 때문이다.

근본적인 해결은 스크레이핑이 아니라 **공식 상품 API·제휴 네트워크 피드**다:

- Best Buy Developer API — 무료, 키 발급만
- eBay Browse API — 무료, 개발자 계정
- Amazon PA-API 5.0 — Associates 승인 + 실판매 유지 필요
- Rakuten Advertising · CJ · Impact — 상품 피드 + 커미션율 + 정식 추적 링크

이 워커는 그 전 단계의 임시 다리다.

## `/rate` 퍼즈 결과 (2026-08-17)

```bash
node site/tests/fuzz-worker.mjs site/worker/index.js 42       # 기존 658 + /rate 89
node site/tests/negcontrol-worker.mjs site/worker/index.js 42  # 음성 대조군
```

**기존 658건 / 실패 0 / SSRF 58건 전부 차단은 그대로**이고, `/rate` 검사 89건이 더해졌다
(시드 42·7·99·2026·1 동일). 검사 내용:

- **적대적 슬러그 64종** — 경로 탈출(`../../etc/passwd`, `shop/nike`, `%2e%2e%2f`), 다른 호스트
  (`evil.com`, `//evil.com`, `http://evil.com`, `nike@evil.com`), SSRF 고전
  (`127.0.0.1`, `169.254.169.254`, `[::1]`, `2130706433`, `metadata.google.internal`),
  헤더 주입(`nike\r\nHost: evil`), 널바이트, 5,000자, 유니코드 동형자(`nıke`).
  **52건 거부 · 12건 수락**, 나간 요청은 전부 못 박힌 두 형태 안에 있었다.
- **리다이렉트 8종** — 자기 도메인·상대경로는 따라가고, 외부 도메인·메타데이터·루프백·
  http 강등·유사 도메인(`www.rakuten.com.evil.com`)은 전부 차단. 차단했을 때 **0%로 뭉개지
  않고 `lookup-failed`** 로 답하는지도 같이 본다.
- **파싱 골든 19케이스** — `pct`·`listed`·`status`·`upTo`·`flat` 을 **행 단위로** 못 박는다.
  개수를 세는 검사로는 "못 찾음 → 0%" 오분류를 못 잡기 때문이다. 봇 차단 두 건은 실패
  **사유 문구**까지 본다(상태만 보면 "못 읽음"과 구분이 안 된다).
- **캐시 4건** — 오리진이 달라도 같은 매장이면 히트(조건 3), 다른 매장이면 미스,
  대소문자만 다르면 같은 항목.
- **로그 0건** — `/rate` 처리 중 `console.*` 이 한 번이라도 불리면 실패(조건 1).

### 음성 대조군 — 검사가 실제로 살아있는지 확인

*"통과했다"는 대상 코드를 일부러 망가뜨려 본 뒤에만 유효하다.* `negcontrol-worker.mjs` 가
변형을 하나씩 먹인 사본으로 하니스를 돌린다. **12개 변형 전부 걸렸고 대조군은 0이다.**

| 망가뜨린 것 | 실패 | 잡은 검사 |
|---|---|---|
| 슬러그 검증을 통째로 끔 | 86 | 못 박힌 포털 URL 밖으로 요청 |
| 슬러그에 점·슬래시 허용 | 36 | 〃 |
| 리다이렉트 호스트 고정 제거 | 7 | 포털 밖으로 나감 · 차단할 리다이렉트를 따라감 |
| **조회 실패를 0%로 뭉갬** | 26 | 파싱 골든 21 + 차단을 0%로 뭉갬 5 |
| Rakuten 홈 리다이렉트를 상점으로 착각 | 2 | 파싱 골든 |
| Up to 표시를 버림(≤7% → 확정 7%) | 1 | 파싱 골든 |

⚠️ 두 가지 함정을 이 과정에서 실제로 밟았다:

1. **`from` 문자열은 한 줄로 쓸 것.** `worker/index.js` 는 CRLF라 `\n` 을 넣은 여러 줄
   패턴은 매치되지 않는다. 다행히 그때는 `소스변경: false` 로 찍혀서 "통과"로 오독되지는
   않는다 — 이 필드가 있는 이유다.
2. **캐시 때문에 정상 동작이 실패로 보일 수 있다.** 적대적 슬러그 목록에 `nike`/`NIKE`/
   `' nike '` 가 함께 있어서, 두 번째부터는 외부 요청이 0건이 된다. 처음엔 이걸
   "포털 2곳으로 안 나갔다"는 실패로 셌는데, 사실은 **슬러그 정규화가 일관됐다는 증거**였다.
   지금은 `요청 2건 또는 (0건 + cached:true)` 로 본다.

### 통과한 것

  같은 접두사 사칭 포함, 전부 허용목록 값으로만 응답

- **원본 HTML 유출 없음** — 범용 프록시로 전용 불가
- **파서 8/8 정답** — JSON-LD 우선 / 자리표시자 `$0.00` 건너뛰기 /
  JSON 키가 본문 텍스트보다 우선(Amazon `$29` vs `"priceAmount":249`) /
  천단위 콤마 / `lowPrice` 폴백 / 음수 가격 거부 / 없으면 `null`
- **인코딩 우회 전부 차단** — `2130706433`(10진), `0x7f000001`(16진),
  `0177.0.0.1`(8진), `127.1`, `127.0.0.1.`, `LOCALHOST`.
  단 이건 코드가 그 경우들을 나열해서가 아니라 **WHATWG `new URL()`이 호스트를
  점4자리로 먼저 정규화해주기 때문**이다. 정규화가 안 도와주는 형태는 아래처럼 뚫린다.

### 처음 발견된 3건 — 호스트 문자열만으로는 목적지를 알 수 없다

| # | 입력 | 정규화 결과 | 왜 통과했나 | 지금 |
|---|---|---|---|---|
| 1 | `[::ffff:127.0.0.1]` | `[::ffff:7f00:1]` | IPv6 검사가 `fc`/`fd`/`fe80:`/`::1`만 봄 → IPv4 매핑 형태를 못 봄 | ✅ 차단 |
| 2 | `169.254.169.254.nip.io` | 그대로 | 이름은 평범한 도메인, DNS가 메타데이터 IP를 가리킴 | ⚠️ 이 패턴만 차단 |
| 3 | 아무 공개 URL | — | `redirect: 'follow'`라서 302로 사설 IP로 넘기면 검사는 최초 URL에만 걸림 | ✅ 차단 |

원 판단은 "**실제 위험도가 낮으니 안 고친다**"였다 — Cloudflare Workers 아이솔레이트엔
옆에 붙은 사설망도, `169.254.169.254`에 응답하는 메타데이터 서비스도 없고, 응답이
**가격 숫자 + title뿐**이라 성공해도 새는 게 거의 없다는 것. 그 분석은 맞다.

그래도 고친 이유는 **"사설망이 없다"가 우리 코드의 성질이 아니라 배포 환경의 성질**이기
때문이다. 이 워커가 Node·컨테이너·다른 클라우드로 옮겨지는 순간 그 보호막은 사라지는데,
정작 수정은 몇 줄이었다. 그리고 문서가 단정한 내용("사설망·루프백·링크로컬로는 요청을
보내지 않는다")을 코드가 못 지키는 상태는 그 자체로 좋지 않다.

### 고친 것 (2026-08-11)

- **IP 리터럴 전면 거부** — `::ffff:`만 덧대는 대신 방침을 바꿨다. 사설 대역 나열은 변종이
  나올 때마다 뚫린다(NAT64 `64:ff9b::`, IPv4 호환 IPv6, 8진/16진 …). 상품 URL이 raw IP인
  경우는 없으므로 **IPv6 리터럴·IPv4 점4자리·정수형·16진형을 형태 불문 거부**한다.
- **리다이렉트 홉마다 재검사** — `redirect:'manual'` + 최대 5홉, `Location`을 현재 URL
  기준으로 해석해 홉마다 `isBlockedHost()`를 다시 통과시킨다.
  실사이트 회귀 확인: `http→https`, `non-www→www` 모두 정상 추적되어 가격 추출 성공.
  악성 302(→`169.254.169.254`)는 "리다이렉트가 허용되지 않은 호스트로 향해"로 차단.
- **본문 스트림 상한** — `res.text()` 전량 버퍼링을 없애고 `MAX_BYTES`(4MB)까지만 읽은 뒤
  `reader.cancel()`. `content-length`가 상한을 넘으면 읽기 전에 거절.
  (실측에서 무한 스트림이 2.1MB에서 끊긴 건 `MAX_HTML` 2M자 조건이 먼저 걸리기 때문 — 위 참조.)
- **로컬 포트 확대** — 3000·4173·5000·5173·8000·8080·8081·8888을 `ALLOW_ORIGINS`에
  **명시적으로** 추가. 정규식 반사는 쓰지 않았다 — 허용목록 밖 값이 헤더에 실리면 안 되고,
  퍼즈 불변식 3번도 그걸 검사하기 때문.

### 여전히 못 막는 것 — DNS 리바인딩 일반

`nip.io`처럼 **이름 안에 IP를 담는** 와일드카드 DNS는 이제 막는다(사설 IP가 박힌 호스트명
거부). 하지만 `evil.com`이 A 레코드로 `10.0.0.1`을 돌려주는 경우는 **이름만 봐서는 알 수
없다.** Workers에선 해석 결과를 볼 수 없어 원리적으로 해결이 안 된다.

완전히 막으려면 **판매처 도메인 허용목록**뿐이다. 계산기엔 이미 `STORE_LIST` 115곳이 있어
재료는 있지만, "아무 URL이나 붙여넣으면 된다"는 지금 UX를 포기해야 해서 도입하지 않았다.
잔여 위험은 **블라인드 SSRF**(내부로 요청을 '보내는' 것까지)이고, 응답은 가격+title로만
나가므로 정보 유출 경로는 아니다.

### 하니스 쪽 함정 (다시 쓸 사람 주의)

실제 `caches.default.match()`는 **매번 새 `Response`를 준다.** 스텁이 `clone()`을
저장했다가 두 번째 히트에서 `Body has already been read` 예외 19건이 났고, 이게
워커 버그처럼 보였다. 스텁은 **본문 텍스트만 저장**하고 `match()`마다 새로 만들어야 한다.
