# probe-data — P3 요율 변동 측정 데이터 전용 브랜치

**여기엔 사이트 코드가 없다.** `rate-probe.jsonl` 하나뿐이다.

## 왜 별도 브랜치인가

`main` 은 GitHub Pages 소스 브랜치다(`build_type: legacy`, `source.branch: main`).
**main 커밋 하나 = 배포 하나**다. 측정 워크플로가 매시간 커밋하면 **하루 24회 배포**가
일어난다. 실제로 그랬다 — 8/25 13:01Z·14:00Z 봇 커밋이 각각 Pages 배포를 일으켰다.

측정 데이터는 **라이브 사이트가 읽지 않는다.** main 에 있을 이유가 없었다.
Pages 는 소스 브랜치에만 반응하므로 이 브랜치에 쌓으면 배포가 0이 된다.

## 이 브랜치의 이력

- **부모 없는(orphan) 커밋**으로 시작한다. 사이트 이력을 끌고 오지 않는다.
- 첫 커밋의 `rate-probe.jsonl` 은 **main 에 쌓여 있던 초기 회차를 그대로 복사**한 것이다.
  회차가 끊기지 않게 하려는 것이다.
- ⚠️ **진짜 데이터는 이 브랜치다.** `main` 에도 같은 이름의 사본이 남아 있는데
  그건 8/25 전환 이전의 잔재이고, **다음에 정당한 배포를 할 때 삭제한다.**
  (지우려고 main 에 커밋하면 그것도 배포라서 지금은 안 지운다.)

## 읽는 법

한 줄 = 한 판매처의 한 회차.

```
{"t":"<UTC ISO>","store":"nike","rk":4,"tcb":6}
```

- `rk` = Rakuten · `tcb` = TopCashback (기본 캐시백 %)
- `rkUpTo`/`tcbUpTo` = 그 값이 "최대 N%" 라는 뜻 (확정치가 아니다)
- `rkFlat` = % 가 아니라 $ 고정 (Amazon 류)
- `rkFail`/`tcbFail` = **못 읽었다.** ⚠️ 값은 `null` 이고 **0 이 아니다** —
  0 으로 적으면 나중에 "그 시각에 0으로 떨어졌다"는 **없는 변동**을 만들어낸다
- 그 회차에 아예 줄이 없는 판매처 = 연속 실패로 **건너뛴** 것 (차단 회피)

## 종료

`scripts/probe-rates.mjs` 가 시작일 +5일이 지나면 스스로 아무것도 안 하고 끝난다.
워크플로를 지우는 걸 누가 잊어도 요청이 계속 나가지 않는다.
